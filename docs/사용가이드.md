# router-proxy 사용 가이드

로컬 LLM 계정 풀 라우팅/로테이션 프록시. 여러 ChatGPT / Command Code 계정을
하나의 엔드포인트로 묶어 사용량에 따라 자동 분산한다. 전부 `$HOME` 기준으로
동작하므로 어떤 macOS 머신에도 동일하게 설치된다. 런타임 요구사항은 Node 18+
(타입 스트리핑을 위한 Node 23+ 권장)뿐이다.

## 포트 한눈에 보기

| 포트 | 서비스 | launchd 서비스명 |
|---|---|---|
| `9090` | cc-accounts 프록시 (Command Code 전용) | `com.cc-accounts.proxy` |
| `9091` | codex-accounts 통합 라우팅 프록시 | `com.codex-accounts.proxy` |
| `9092` | 제어 API + 웹 대시보드 | `com.codex-accounts.control` |
| — | 사용량 수집기 (5분 간격) | `com.codex-accounts.quota` |

## 1. 설치

```bash
./install.sh               # 프록시 2종 + quota 수집기 + launchd 에이전트 설치
./install.sh --dry-run     # 변경 없이 진행 상황만 출력
./install.sh --uninstall   # launchd 에이전트/plist 제거 (스크립트·데이터는 유지)
```

설치 위치 (모두 `$HOME` 아래):

- 스크립트: `~/.cc-accounts/`, `~/.codex-accounts/` — launchd는 `~/Documents` 아래
  스크립트 실행을 TCC가 막으므로 여기서 실행된다
- plist: `~/Library/LaunchAgents/`
- 데이터: `~/Documents/codex-accounts/` (`accounts.db` + `encryption.key`)

### 설치 확인

```bash
curl http://127.0.0.1:9091/healthz   # 통합 프록시: {"ok":true,"providers":{...},"uptime_s":...}
curl http://127.0.0.1:9090/healthz   # cc 프록시: {"ok":true,"accounts":N,...}
curl http://127.0.0.1:9090/provider/v1/models
```

## 2. 계정 추가

### ChatGPT 계정 (디바이스 로그인)

```bash
node ~/.codex-accounts/login.ts        # 빈 슬롯(a/b/c...) 자동 할당
node ~/.codex-accounts/login.ts b      # 특정 슬롯 덮어쓰기
```

출력된 디바이스 코드를 브라우저에서 https://auth.openai.com/codex/device 에
입력하면 끝. 계정은 Fernet 암호화되어 `accounts.db`에 저장된다.

### ChatGPT 토큰 갱신

```bash
node ~/.codex-accounts/export-tokens.ts --refresh   # 내장 계정 전체 갱신
```

리프레시 토큰은 1회용이라 갱신 시마다 `token`/`refresh`가 모두 로테이션되어
저장된다. 갱신 실패(계정 만료) 시 `login.ts`로 재등록한다.

### Command Code 키

```bash
~/.cc-accounts/add-account.sh a sk-...   # 키 직접 입력 (암호화 저장)
~/.cc-accounts/add-account.sh b           # 브라우저 로그인 플로우 (cmd login)
```

## 3. 클라이언트 연결

### codex CLI → 통합 프록시 (9091)

`~/.codex/config.toml`:

```toml
model = "gpt-5.6-sol"
model_provider = "codex-accounts"

[model_providers.codex-accounts]
name = "codex-accounts"
base_url = "http://127.0.0.1:9091"
wire_api = "responses"
```

`wire_api = "responses"`인 codex는 `{base_url}/responses`, `{base_url}/models`로
요청하며, 프록시가 이를 ChatGPT 계정 풀로 매핑한다. 환경변수 토큰 없이도
동작한다 — `~/.codex/auth.json`의 `access_token`을 프록시가 선택한 계정의
`account_id`와 일치할 때만 주입한다 (불일치 시 `accounts.db`의 계정 토큰 사용).

자세한 배경: [codex-config-proxy-wiring.md](codex-config-proxy-wiring.md)

### Command Code 직접 (9090)

```bash
COMMANDCODE_SANDBOX=true COMMANDCODE_API_URL=http://127.0.0.1:9090 cmd ...
```

## 4. 라우팅 규칙 (:9091)

```
/responses, /models, /backend-api/codex/*  → ChatGPT 계정 풀 (Bearer 토큰 로테이션)
/provider/v1/*                             → Command Code (x-api-key 로테이션)
/v1/*                                      → 요청 JSON의 model 필드로 프로바이더 매칭
```

`/v1/*`은 각 프로바이더의 `model_pattern` 정규식과 모델명을 매칭하며,
catch-all(`.*`) 프로바이더는 항상 순회 마지막으로 정렬된다 (등록 순서가 아니라
패턴 구체성이 우선).

### 사용량 기반 스코어링

quota 수집기가 5분마다 양쪽 풀의 사용량을 조회해 `usage_snapshots`에 저장하고,
프록시는 각 계정을 아래처럼 스코어링한다:

```
score = remaining% / max(time_to_reset, 60s)
```

- 남은 쿼터가 많고 리셋이 임박한 계정을 우선 사용 (쿼터 낭비 방지)
- 세션 요청은 `x-session-id` 해시로 계정 고정 (소진된 계정은 제외)
- 무상태 요청은 스코어 가중 랜덤 선택
- 401/429는 같은 풀의 다음 계정으로 재시도 (mid-stream 재시도 없음)

수동 수집: `node ~/.codex-accounts/quota.ts`

## 5. 대시보드 & 제어 API (:9092)

브라우저에서 http://127.0.0.1:9092/ 열기. 프로바이더별 칸반 뷰로 각 카드에
남은 %, 리셋 카운트다운, 플랜, weight, 인라인 컨트롤(일시정지/burn/weight/
라벨/삭제)이 표시되고 30초마다 자동 갱신된다. 서빙 업체(providers) 패널에서
새 벤더(id, name, base URL, path prefix, auth header, model regex) 추가 가능.

```
GET    /api/accounts                            → 계정 목록 (QuotaBar 호환)
GET    /api/usage                               → 최신 사용량 스냅샷
GET    /api/health                              → 상태
POST   /api/accounts/:pool/:slot/enabled        → {"enabled":true|false} 일시정지/재개
POST   /api/accounts/:pool/:slot/weight         → {"weight":1.5} 라우팅 가중치
POST   /api/accounts/:pool/:slot/label          → {"label":"work"} 이름 변경
POST   /api/accounts/:pool/:slot/burn           → {"burn":1} burn 우선순위 (0-3)
DELETE /api/accounts/:pool/:slot                → 계정 삭제
GET    /api/providers                           → 프로바이더 목록
POST   /api/providers                           → 추가 {id,name,baseUrl,pathPrefix,authHeader,modelPattern}
DELETE /api/providers/:id                       → 삭제
POST   /api/accounts                            → 계정 추가 {providerId,slot,token,...}
```

- `pool`/`providerId`는 프로바이더 id (`chatgpt`, `commandcode`, 커스텀…),
  `slot`은 계정 id (`a`, `b`, `c`, …)
- 비활성화된 계정은 라우팅에서 제외, weight는 사용량 스코어에 곱해짐
- **Burn**(🔥): ×1..×3 우선 소진 — 스코어 무관하게 먼저 사용, ×3에서 다시
  클릭하면 0으로 리셋
- QuotaBar 연동: `CODEXBAR_ENDPOINT=http://127.0.0.1:9092`

CLI 등가 명령: `node ~/.codex-accounts/db.ts list|usage|enable|disable|weight|label|del|providers|provider-add|provider-del`

## 6. 운영

### 재시작 / 상태 확인

```bash
launchctl kickstart -k gui/$(id -u)/com.codex-accounts.proxy
launchctl kickstart -k gui/$(id -u)/com.cc-accounts.proxy
launchctl kickstart -k gui/$(id -u)/com.codex-accounts.control
curl http://127.0.0.1:9091/healthz
```

`EADDRINUSE (9091)`는 launchd가 이미 포트를 점유 중이라는 뜻이므로 정상 —
수동 실행 대신 `launchctl kickstart`로 재시작한다.

### 새 머신 마이그레이션

1. `./install.sh`
2. `~/Documents/codex-accounts/`의 `accounts.db` + `encryption.key` **한 쌍**을
   그대로 덮어쓰기 (두 파일은 분리 불가 — 키가 다르면 복호화 불가)
3. launchd 재시작

### 환경변수

| 변수 | 기본값 | 용도 |
|---|---|---|
| `CC_PROXY_PORT` | `9091` | 통합 프록시 포트 (cc 프록시 기본은 9090) |
| `CODEX_ACCOUNTS_DIR` | `~/Documents/codex-accounts` | DB + encryption.key 디렉토리 |
| `CODEX_ACCOUNTS_DB` | `$CODEX_ACCOUNTS_DIR/accounts.db` | DB 경로 오버라이드 |
| `CODEX_ACCOUNTS_KEY` | `$CODEX_ACCOUNTS_DIR/encryption.key` | 키 경로 오버라이드 |
| `CONTROL_PORT` | `9092` | 제어 API 포트 |
| `PROXY_UPSTREAM_TIMEOUT_MS` | `90000` | 업스트림 응답 헤더 대기 상한 (dead keep-alive 방어) |
| `PROXY_STREAM_IDLE_TIMEOUT_MS` | `180000` | mid-stream 무음 감시 (0 = off). 헤더 후 N초간 데이터 0이면 스트림 종료 |
| `PROXY_MAX_UPSTREAM_ATTEMPTS` | `3` | 요청당 최대 업스트림 시도 (401/429/타임아웃/일시적 오류만 재시도) |
| `CODEX_DASHBOARD` | `~/.codex-accounts/dashboard.html` | 대시보드 HTML 경로 |

## 7. 보안 주의사항

- 키/토큰은 `accounts.db`에 **Fernet(AES-128-CBC + HMAC-SHA256) 암호화**로
  저장되고, 키는 별도 `encryption.key`(chmod 600)에 있다. **둘 다 git에
  커밋 금지** — 리포는 코드/템플릿만 담는다.
- `auth.openai.com`의 Cloudflare가 기본 HTTP 클라이언트 UA를 차단하므로
  (HTTP 530 `cf_route_error`) 스크립트는 브라우저 UA를 보낸다.
- Node의 `node:sqlite` 실험적 경고는 무해하다.

## 문제 해결 빠른 참조

| 증상 | 조치 |
|---|---|
| 요청이 안 감 | `curl 127.0.0.1:9091/healthz` → 죽었으면 `launchctl kickstart` |
| 9091 포트 충돌 | 정상 (launchd 점유). 수동 실행 금지 |
| 계정 401 | `export-tokens.ts --refresh` → 실패 시 `login.ts` 재등록 |
| SSE 응답이 끊김 | mid-stream 재시도는 설계상 없음. `PROXY_STREAM_IDLE_TIMEOUT_MS` 확인 |
| TLS 영구 오류 | 자동 502 처리 — 업스트림 인증서/프록시 설정 확인 |
